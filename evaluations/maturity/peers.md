# What a researcher can check in each workflow

A run record can identify where a number came from. To test the conclusion, a reviewer also needs to know why that comparison was chosen and what observation would have counted against it. The comparison uses AI4Sci Workflow at Git revision `1c5d24060e1a1a67b551b1724427db3f77fefcb8`. The studies below are from that revision.

## Reference tasks

| Research task | Evidence in the AI4Sci baseline |
|---|---|
| Trace a claim to its source | The two arms of the [reading comparison](../paired-confirmation/results.md) both earned 8/8 on supplied excerpts. That tests interpretation with sources in hand, not recall when searching the literature. |
| Compare models on the same observations | The [penguin reviewer](../../examples/penguins/research/review.md) reconstructed a linear fit from the training rows and scored both models on the same 119 later observations. Rerunning the independent script recovered the reported mean reduction in absolute error of 384.706734152 g. The comparison was with the training mean, not the best constant for absolute error. |
| Decide whether an apparent finding holds | On [DiscoveryBench astronomy query 771](../discoverybench-771/README.md), the workflow missed the organizer's conditional hypothesis. All 494 recorded responses were identical. A second analysis confirmed all 13 reported contrasts. Recovering a reference hypothesis and reporting what the table supports gave different answers on this task. |
| Repair or hand off a draft | In an [integration study](../paired-pilot/integration/result.md), the audit caught a mismatch between a marked sentence and its evidence. The corrected Markdown passed. The [quadrature review](../../examples/opencode-study/research/review.md) separately recomputed all twelve estimates without the analysis program. At `1c5d240` the audit checked marked Markdown, CSV cells and quotations. The [final-file check](../../checks/submission.md) in the current checkout was added later. |

**Source inspection** means reading a versioned implementation or instructions. **Observed artifact** means inspecting a particular output. **Recalculation** means checking the named quantity, not rerunning the whole system. Results attributed to a paper are the authors' evaluations. No paired end-to-end run with these peers was performed here, so comparative success rates are unknown.

## Three research workbenches

**Synthetic Sciences OpenScience — reconstruct an analysis behind a report.** Given a research goal and local files, the agent can search, run Python or R, and decide whether a result supports a draft claim. Its [sources protocol](https://github.com/synthetic-sciences/openscience/blob/dbb60cba76afa518941a70ec4c25febba3114f4b/backend/cli/skills/core/sources/SKILL.md) calls for a table of claims, passages and judgments. Its [kernel test](https://github.com/synthetic-sciences/openscience/blob/dbb60cba76afa518941a70ec4c25febba3114f4b/backend/cli/test/science/kernel-provenance.test.ts) checks that the stored run identifies the code, interpreter and outputs. This gives a recipient more execution context than the baseline's required command and output list.

*Recalculation:* The bundled [temperature example](https://github.com/synthetic-sciences/openscience/tree/dbb60cba76afa518941a70ec4c25febba3114f4b/backend/cli/skills/coding/timesfm-forecasting/examples/global-temperature) supplies 36 monthly inputs and 12 forecasts. The mean of `point_forecast` in the saved CSV is 1.18594925 °C, consistent with the summary's 1.19 °C. In the same file, `q10` exceeds `q20` in **all twelve months**. The interval labels need checking against the model's output convention before using the uncertainty estimates. This is a check on a bundled example, not on forecast accuracy or an autonomous workbench run. The project's [benchmark notice](https://www.openscience.sh/benchmark) also identifies scoring differences in its own comparisons. **Use:** retain the passage-level judgment already credited in [Sources and reuse](../../SOURCES.md). Ask the reviewer to test the meaning and ordering of interval columns as well as transcription. No workbench dependency is needed.

**AIPOCH Open-Science — replay a result received from another investigator.** A sender selects a conversation branch and evidence for a portable `.science` package. Given a captured recipe, input identities and environment requirements, the [replay package](https://github.com/aipoch/open-science/blob/9d42705b02783d4ac96a55f183d3c99998e1ee13/packages/reproducibility/README.md) can execute the recorded steps through a host runtime and compare outputs. That addresses a different problem from AI4Sci's read-only audit. AIPOCH's [ten-study evaluation](https://aipoch.com/benchmark/open-science) used one sealed run per agent and study and reports local, not official, scores. It did not include this baseline.

*Component test:* Given three categorical assignments, the [scientific table comparator](https://github.com/aipoch/open-science/blob/9d42705b02783d4ac96a55f183d3c99998e1ee13/packages/reproducibility/src/scientific-output-comparison.ts) reported `does-not-meet` when only the replay omitted ID 3. When both tables omitted it, the two remaining assignments earned an adjusted Rand index of 1 and `meets-criteria`. Agreement is correct for the data compared. Neither table can reveal the jointly missing observation. **Use:** keep key-aligned replay separate from completeness against the *planned* rows. In AI4Sci, put indispensable cells in the frozen plan. For transfer of the actual notebook environment and branch, use AIPOCH's package rather than implying a Markdown handoff supplies one. The upstream package is [Apache-2.0](https://github.com/aipoch/open-science/blob/9d42705b02783d4ac96a55f183d3c99998e1ee13/packages/reproducibility/LICENSE). The local comparator is a separate implementation.

**AI4S Research Open Science Desktop — resume a study and challenge its interpretation.** A project can retain sessions, notebooks and runs. Given a report, analysis code and preregistration, its [scanner](https://github.com/ai4s-research/open-science/blob/1dc2cbd8eb6b58887a1e6c41f80c797051f07700/runtime/skills/core/stats-integrity/stats_integrity_check.py) returns a structured `review` block about causal wording, undeclared analysis terms and unseeded randomness. The separate [traceability review](https://github.com/ai4s-research/open-science/blob/1dc2cbd8eb6b58887a1e6c41f80c797051f07700/runtime/skills/core/traceability-review/SKILL.md) asks the reader to resolve sources and check figures. The [benchmark snapshot](https://github.com/InternScience/ResearchClawBench-Home/blob/6be2ab8ca379bd3ad0c1e83d86c985e11af972af/data/leaderboard_only_runs.json) records `Open Science`, Claude Opus 4.8, on `Astronomy_000` with `details_exported: false`. The score supplies neither that run's manuscript nor its code revision.

*Component test:* The interpretation check flagged “Our regression proves that temperature causes variability.” It gave no finding for “The mean error was 0.50.” or for the same sentence with 0.90. This checks wording, not the number. **Use:** AI4Sci already ships the [MIT-licensed scanner](../../vendor/ai4s-desktop/LICENSE) and tests. Pair its flags with a row-level evidence check and independent calculation. To resume work, an OpenCode session can also use persistent history and, when configured, Magic Context. The baseline's short handoff serves a different reader: a collaborator with the study files but without the analyst's session history.

## Choosing, running and revising experiments

**ARIS — decide whether a revision answers a referee.** Given a research directory and a draft, its [review loop](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/skills/auto-review-loop/SKILL.md) routes work to a reviewer, asks the executor to address findings and records successive assessments in `review-stage/AUTO_REVIEW.md`. It saves reviewer state and has a round limit. The [project's submission example](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/README.md) explicitly distinguishes a simulated conference review from an official decision. *Source inspection.* **Use:** keep the original objection, changed artifact and reply together. Check the decisive result from inputs as in the quadrature review. A second model's recommendation alone does not perform that check. The [MIT-licensed source](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/LICENSE) also informed AI4Sci's review and image integration. A particular reviewer backend need not be mandatory.

**alphaXiv OpenResearch — choose a follow-up without losing the parent result.** Its [experiment tree](https://github.com/alphaXiv/OpenResearch/blob/b74275826e1a5e2fb2c65cc6497d5683a1f07818/agent-skills/orx-experiment-tree/SKILL.md) starts with working code and a run command. A child inherits both. The researcher can compare its metrics and code diff with its parent, promote a promising variant, or retain a valid negative result as a finished node. A run that fails to exercise the intended method can instead be repaired. *Source inspection.* The baseline can declare common conditions but does not automatically maintain these branches. **Use:** retain the parent result and identify which change the next run tests. A child chosen after seeing the score is exploratory until it has an independent test. Apply the method without requiring a second scheduler. The protocol is [MIT-licensed](https://github.com/alphaXiv/OpenResearch/blob/b74275826e1a5e2fb2c65cc6497d5683a1f07818/LICENSE).

**EvoScientist — avoid repeating an infeasible idea.** In the [system study](https://arxiv.org/html/2603.08127v2), ideation memory records promising and unsuccessful directions. Experiment memory records lessons from code trajectories. An analyst can use those lessons to choose an implementation, then produce code and a manuscript. One [industrial time-series submission](https://airaxiv.com/papers/view/2510.0020/) has a public manuscript and decision. The authors report six selected ideas turned into six accepted submissions at ICAIS 2025. The [organizers](https://icais.ai/2025/call4papers/) describe the venue as **non-archival**. This is evidence of assessed manuscripts, not six archival publications or a success rate for arbitrary starting ideas. The [later software revision](https://github.com/EvoScientist/EvoScientist/blob/850df6f075505d74b69e34933b4d0c989422b094/README.md) additionally documents line-delimited JSON events. *Observed submission and source inspection, without rerunning the models.* **Use:** record a rejected direction and its reason in the handoff. Do not feed earlier solutions into a fresh confirmation or credit a remembered result as a new observation.

**Sakana AI Scientist-v2 — test an ML hypothesis through competing implementations.** From a topic in Markdown, the [release](https://github.com/SakanaAI/AI-Scientist-v2/blob/96bd51617cfdbb494a9fc283af00fe090edfae48/README.md) generates structured ideas in JSON, searches a tree of GPU experiments and produces a PDF manuscript. In the [workshop experiment](https://github.com/SakanaAI/AI-Scientist-ICLR2025-Workshop-Experiment/tree/c05036b2e0dcc17056abfba398184f51a93087ca), one of three human-selected submissions received scores of 6, 7 and 6. It reported a negative regularization result. All were [withdrawn before publication](https://sakana.ai/ai-scientist-first-publication/). The authors' [code inspection](https://arxiv.org/html/2504.08066) identified possible training/test overlap in the favorably reviewed paper. *Observed review records and author assessment.* **Use:** report failed ablations and check split membership from raw IDs, as in the penguin study. Do not import the GPU stack or treat a review score as validation of the split. The implementation has a [custom source license](https://github.com/SakanaAI/AI-Scientist-v2/blob/96bd51617cfdbb494a9fc283af00fe090edfae48/LICENSE).

**Denario — develop a method from data, then typeset the result.** The [gravitational-wave example](https://github.com/Denario-AI/Denario/blob/f6cc751603f2caed7524cc22b31652243c7b7c97/examples/full_workflow.py) takes two CSV files and a Markdown data description, selects an idea and a method, computes results and requests an astronomy-journal article. The example explicitly disables adding citations. The [output archive](https://github.com/Denario-AI/DenarioExamplePapers/blob/350f6403a32a94f3010c833d1ac1a504924521bd/README.md) includes a [GW231123 project](https://users.flatironinstitute.org/~fvillaescusa/Denario/Astrophysics/GW/Iteration2/Project1/) with a PDF named `paper_v2_no_citations.pdf`. The archive describes its selection as unfiltered. Publication of the [Denario system study in PRX Intelligence](https://doi.org/10.1103/kk55-gc95) is a separate event from depositing those drafts. *Observed project and source inspection.* **Use:** add a check of the actual typeset figures, references and conclusion when providing a submission file. At baseline the audit ends at Markdown. Do not embed the [GPLv3 implementation](https://github.com/Denario-AI/Denario/blob/f6cc751603f2caed7524cc22b31652243c7b7c97/LICENSE) to add formatting.

**Agent Laboratory — decide when human input changes the plan.** Starting from a human's idea, the system reviews literature, experiments and writes a report. In co-pilot mode a researcher can approve or send back a stage. Its [implementation](https://github.com/SamuelSchmidgall/AgentLaboratory/blob/d9017d90e329112d2a80b7712f37ee9094d2cd27/ai_lab_repo.py) saves `src/run_experiments.py`, `src/experiment_output.log` and `report.txt`. The [published evaluation](https://aclanthology.org/2025.findings-emnlp.320/) compares human judgments with model reviews. The authors report mean overall ratings of 3.8/10 from people and 6.1/10 from the automatic reviewer on the autonomous papers. These are judgments in a study, not venue decisions. *Source inspection and author evaluation.* **Use:** ask for intervention when a design choice changes the question or control. Keep the human's reason and the old result so a later reviewer can assess what changed. An approval after each routine operation adds little to a bounded numerical study.

**Kosmos — choose which finding from broad exploration warrants confirmation.** From a dataset and an open-ended objective, a shared world model directs parallel literature and data-analysis tasks. Scientific reports link to publications or Jupyter notebooks. The [solar-cell figure archive](https://github.com/EdisonScientific/kosmos-figures/tree/819447258cb53782fb3b7ddd63be8d65acf8f078/Figure_3_perovskite_solar_cell) includes a workbook, notebooks, CSV summaries and rendered figures for an analysis of device performance. These files permit inspection of the reported association without providing the discovery service itself. In the [authors' evaluation, §2.1](https://arxiv.org/html/2511.02824v2), experts checked 102 statements from three reports. They supported 85.5% of analysis statements but only 57.9% of synthesis statements. *Observed archive and author evaluation.* **Use:** label a measured association separately from an interpretation that joins it to earlier work. Freeze a discriminating follow-up on fresh evidence rather than treating the best story from a search as confirmed. The baseline astronomy case illustrates why checking all reported numbers still leaves a discovery question open.

## Specialists by research decision

| Decision and primary evidence | What the specialist returns | Consequence for an AI4Sci study |
|---|---|---|
| **Which passages answer a question?** [PaperQA2, release v2026.08.12](https://github.com/Future-House/paper-qa/blob/v2026.08.12/README.md) and [OpenScholar, inference code](https://github.com/AkariAsai/OpenScholar/blob/0e9b8fb912273d3dae39e593da86e4f6d3bf8de1/run.py). Source inspection. | PaperQA2 indexes a supplied collection and retrieves, reranks and summarizes passages into a cited answer. OpenScholar retrieves from a larger literature index and refines a multi-paper answer, with inference results saved as JSON. Its [published study](https://doi.org/10.1038/s41586-025-10072-4) reports that some relevant papers are missed. | Use either for candidate passages when the two-note reading task is too narrow. Check the decisive passage, population and counterexample against the original. Record a quoted value as source-reported, not as a new computation. Neither index needs to ship with the workflow. |
| **Which code change improves a fixed metric?** [AIDE](https://github.com/WecoAI/aideml/blob/b39bb0e145e7785bcbc29e1b5d123f01d8f04c2c/README.md), [autoresearch](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md) and [Heuresis](https://github.com/a-antoniades/Heuresis/blob/51c737575090271075d5751f26ef6183c8b282b0/docs/concepts.md). Source inspection and author evaluation. | AIDE starts with data, a goal and a metric, branches Python solutions and saves `best_solution.py` plus the tree. autoresearch changes `train.py` under a fixed five-minute training budget and logs commit, validation bits per byte, memory and keep/discard/crash in `results.tsv`. Heuresis branches from a task harness and parent results, writing `idea.md`, edited code and grading artifacts. Its [study](https://arxiv.org/html/2606.25198v2) found 40 confirmed fabrications among 1,628 scored runs examined for that issue. | Use fixed compute, retained losses and an evaluator outside the editable experiment. Recompute the chosen metric from saved predictions as in the penguin check. Repeatedly selecting against one validation set creates a new need for untouched test data. Do not adopt an open-ended training loop as the default. |
| **What observation would satisfy this request?** [AutoSciRub](https://github.com/zjunlp/AutoSciRub/blob/2c6c58392ee6399e08f2526e35176f0e2c716e16/README.md) and its [astronomy run archive](https://huggingface.co/datasets/huminclu/autoscirub-rcb-main-exp/tree/6a412f394d44b021d26d548d943a4106ff5e1c09/workspaces-cc%2B/Astronomy_000_20260630_163902). Source inspection and observed file inventory. | Given instructions, literature and data, it specifies evidence per criterion in `executable_rubric.json`, records checks in `verification_report.json` and revises the unmet items. The archived run contains analysis code and numerical exclusion results in NPZ format. A criterion omitted during planning will not appear among the failed checks. | The baseline already incorporates the [two MIT-licensed protocols](../../SOURCES.md). Before freezing, ask whether satisfying every criterion could still leave a rival explanation open. After a repair, recheck the conclusion against the changed observation, not just the rubric status. |
| **Which rival hypothesis should be tested?** [Google Co-Scientist, system paper and supplements](https://doi.org/10.1038/s41586-026-10644-y). Published mechanism and author evaluation. | Given an objective, constraints and prior evidence, agents generate and critique proposals, rank them in a tournament and refine them. The artifacts are ranked hypotheses and research proposals. The paper publishes pseudocode and prompts, not the full service implementation. | Use the comparison of rivals, not the service as a dependency. For a constant astronomy outcome, specify which new observation would distinguish an effect hidden by rounding from a physically invariant response. A tournament rank cannot supply that observation. |
| **When should new measurements change the shortlist?** [Robin, published study](https://doi.org/10.1038/s41586-026-10652-y) and [released artifacts](https://github.com/Future-House/robin/blob/4a5cce310f3bc7663a67117db88af43b84733ffe/README.md). Source inspection and author evaluation. | A domain question leads to literature-grounded rankings. When scientists supply measurements, the analysis can change subsequent rankings. The release describes ranking CSVs, text summaries and an optional consensus-results CSV. The measurements in the study were collected by people, and the released analysis path calls a hosted service. | Transfer the decision, not the domain tools: on a forecast study, preserve the initial ranking of candidate explanations and the new observations that changed it. Mark a follow-up needing uncollected data as pending. |
| **Which objection changes a team's design?** [Virtual Lab, published study](https://doi.org/10.1038/s41586-025-09442-9) and [meeting writer](https://github.com/zou-group/virtual_lab/blob/8a3a4fd9ccc0cd297bd523751e03bc9527c91832/src/virtual_lab/utils.py). Source inspection and author evaluation. | A researcher supplies an agenda. Investigator and specialist agents discuss the question in team or individual meetings, with human feedback. The writer saves the discussion in JSON and Markdown. The article reports separate experimental validation. A meeting transcript identifies who proposed a test, not its outcome. | In a numerical study, retain the objection that changes the control and the reason for the change. Give the reviewer the resulting comparison and inputs instead of substituting a transcript for recomputation. |
| **Does a tool result justify the answer?** [ChemCrow, published evaluation](https://doi.org/10.1038/s42256-024-00832-8) and [public implementation](https://github.com/ur-whitelab/chemcrow-public/blob/e7ebd5193334ac1d8dea137b635721c7cb470d33/README.md). Source inspection and author evaluation. | From a domain query the agent selects a tool, receives an observation and returns an answer. Experts and the model grader preferred different answers. The public implementation provides only a subset of the original tools. | Use the underlying observation to check a computed quantity and identify the tool version. Do not require chemistry services for a general computational workflow or interpret an unavailable tool as a completed experiment. |

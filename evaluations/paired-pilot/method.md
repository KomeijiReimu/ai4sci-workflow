# Replay notes: offline paired pilot

Two small, fresh tasks were each given to two new OpenCode 2.4.1 sessions. Counts uses an original fictional primary registry and conflicting newsletter; reading uses local, versioned primary-method excerpts plus a citation and a deliberately unreliable digest, not an online literature search. No tool installation or data retrieval was requested. The reading excerpt files add headers, source locators and visible omission markers to CPython/NumPy text; their licenses are in `source-notices/`.

**Blinding and controls.** The two arms started with byte-identical input trees. The same actual cwd and `PWD` (`/mnt`), read-only kit (`/media`), model (`deepseek/deepseek-flash`), built-in `build` agent, allowed tools and 360 s wall cap were used. Within each pair the only prompt difference was the appended line in `prompts/workflow-append.txt`. Distinct private user/mount/PID namespaces hid the workstation home, other sessions, global account config, skills/plugins, the task controller and key. Each standalone process used fresh private state and standard built-in tools. Only cached model metadata and the selected inference settings were privately supplied. This was not the workstation’s normal customized environment; OpenCode’s own prompts/tools and the model's prior knowledge still existed. The scorer was **not** blinded. Generation was not seeded, there was one pair per task, and wall caps—not token usage, achieved latency or cost—were matched. No delegation. There was no audit requested for reading.

**Invocation.** Material session command (the full prompt supplied as the final single argument):

```sh
/srv/bin/opencode --standalone --log-level error run --archived --model deepseek/deepseek-flash --agent build --format json --auto --title 'Matched offline research task' "$message"
```

`cwd=/mnt` and `PWD=/mnt` were set before this command. To replay on a different machine use its OpenCode binary, the same available model if possible, a fresh external directory, and a read-only workflow checkout; adapt both literal paths in the prompts together for both arms. Copy only `inputs/<task>/` to each fresh workspace. Keep prompts, rubric, results, and the other arm outside it. To check the historical outputs, combine the `inputs/<task>/` files with the corresponding `outcomes/<task>/<arm>/` files; no LLM is required for rerunning the delivered Python scripts. The complete-kit comparison and functional smoke test used a different archived kit digest than the original pair. `execution.json` records which kit was used for each evaluator command.

**Attempts.** Two initial registry launches returned zero model text and zero tool calls because putting `/mnt` under a private mount hid WSL's DNS resolver. Both were stopped, exit 143, at 94.759 s (plain) and 94.754 s (workflow). A namespace-only repair preserved the original resolver, with both arms otherwise unchanged. All four substantive sessions completed with client exit 0; times are in `execution.json`. Original failed launches are retained locally as transport preflights, not scored zeros and not discarded scientific answers. A concurrent pair is not an independent repeated estimate of model performance.

**Kit caveat.** The comparison snapshot was created from files returned by `git ls-files` but containing the then-current *worktree bytes*. Seven of 22 captured files differed from Git HEAD `0a52a31204d05548d6cb2708944ad01eb7178f2a`; `kit-provenance.json` lists their hashes. The new `checks/sources.py` was untracked and missing. Consequently the registry workflow's own `freeze` command failed; it wrote the equivalent SHA-256/LF file itself before the formal analysis. Its own audit failed at import (exit 1, **not** a normally completed “incomplete” JSON audit). The study remained unchanged. In separate evaluator runs, the original partial kit reproduced that error and a complete archived runtime accepted the same study. That later success does not repair the historical CLI attempt. No second workflow answer replaces it. A distinct unscored external integration study used another question, fresh inputs and the complete kit; its process evidence is separate from either score.

**Scope of evidence.** This packet addresses one small numerical analysis and one local primary-document reading task; no performance guarantee, general literature-discovery quality, causal merit of the workflow, or comparison of published token prices follows. The answer key was written before running the model, not externally timestamped. `frozen-inputs.json` lists byte digests using the original capture paths (`control/key.md` corresponds to `frozen-rubric.md`). Original controls, all attempts and two kit snapshots are archived privately. No inference credentials, endpoints, session identifiers or raw transcripts are part of this packet.

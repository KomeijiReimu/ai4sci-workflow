# Review the evidence

Read the frozen criteria, draft, raw results, code and actual source passages. First find important **unmarked** assertions, especially in the abstract, results and conclusions; a machine can only check the claims someone declared. Compare populations, data splits, denominators, effect size and units, direction of change and how broadly each sentence is worded. Resolve a DOI to metadata before trusting attribution. A matching quote alone does not establish entailment. Recompute at least the decisive metric independently from its inputs where possible.

For a formal study run with this workflow (including a new Markdown study), run `python3 "$KIT/ai4sci.py" audit "$STUDY"` and report its exit code and failures. For an outside manuscript, review the supplied evidence and identify missing records without reconstructing them. If a new supplement was run, audit its directory; that audit does not validate the original study. An advice-only review needs no study audit. On statistical studies optionally run `ai4sci.py stats` on explicit code/report/plan paths. Review the actual findings; absence of a preregistration document means adherence was not checked. Check multiple comparisons or causal inference where relevant. A lint result is not a scientific verdict.

For each issue give the claim/criterion ID, evidence location, what conflicts or is missing, consequence and smallest repair. Separate blockers from observations. Give three answers: did execution finish, which claims are supported (or narrower/contradicted/untested), and is the manuscript honest and ready to deliver? A completed run with a well-supported failure to replicate can yield a deliverable report. Return issues to the original owner for one targeted repair and recheck; retain outstanding issues instead of declaring success.

For a formal draft persist these findings in `$STUDY/research/review.md`. Record who performed the check (separate reviewer or author self-check), the inputs and method used for independent recalculation or source verification, the actual comparison and unresolved limits. Do not label a self-check or shared-context review blind. Link the review from the study's existing `research/handoff.md`; on resume read both files and check what changed before repeating any work.

Review the file the author asked to deliver, following [the submission route](../ai4sci-paper/references/submission.md). For a revised Markdown manuscript, have an independent reader open the exact `.md` and check each reply against the changed passage and cited evidence. If only the author checks it, report a self-check, not independent review. Markdown alone needs neither `submission.json` nor a Word/PDF check. For a formal venue Word/PDF package, inspect the actual rendered file, bind the review to those bytes, the canonical manuscript and the ledger, and run `audit --submission` before handoff. In either format, read the abstract, captions and conclusion for unsupported wording, check revised figures and tables against the outputs, distinguish independent evidence from reanalysis, and report unresolved discrepancies.

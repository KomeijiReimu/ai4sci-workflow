# Review the evidence

For a [publication-oriented study](../ai4sci/references/publication.md), use a strong final reviewer who did not perform the analysis or write the paper. If that reviewer materially shaped the design, use a fresh qualified session. Check the version being returned and follow any material correction into the replacement file before recording the final review. If independent review is unavailable, label the work self-checked and the independent review pending.

Read the manuscript, its cited evidence and the criteria, raw results and code available for this work. First find important **unmarked** assertions, especially in the abstract, results and conclusions. A machine can only check the claims someone declared. Compare populations, data splits, denominators, effect size and units, direction of change and how broadly each sentence is worded. Resolve a DOI to metadata before trusting attribution. A matching quote alone does not establish entailment. Recompute at least the decisive metric independently from its inputs where possible.

For a formal Markdown study run with this workflow, run `python3 "$KIT/ai4sci.py" audit "$STUDY"` and report its exit code and failures. Use the Word/PDF route below for formal packages. For an outside manuscript, review the supplied evidence and identify missing records without reconstructing them. An advice-only review needs no study audit. On statistical studies optionally run `ai4sci.py stats` on explicit code/report/plan paths. Review the actual findings and identify any preregistration document used to check adherence. Check multiple comparisons or causal inference where relevant. A lint result is not a scientific verdict.

For each issue identify the criterion or manuscript passage, the evidence location, what conflicts or is missing, the consequence and the smallest repair. Separate blockers from observations. State which claims are supported, narrower than stated, contradicted or untested, and whether the manuscript is ready to deliver. For an experiment, also state whether execution finished. A completed run with a well-supported failure to replicate can yield a deliverable report. Return issues to the original owner for one targeted repair and recheck. Retain outstanding issues instead of declaring success.

Record who performed the check (separate reviewer or author self-check), the inputs and method used for recalculation or source verification, the actual comparison and unresolved limits. Do not label a self-check or shared-context review blind. For a native formal draft, save these findings in `$STUDY/research/review.md` and link them from the existing `research/handoff.md`. For an outside revision, return the findings with the exact author files and reply. On resume read the prior findings and check what changed before repeating any work.

When a study keeps a [review-round trail](../../checks/rounds.md), compare the original comments and prior reply with the new manuscript and reply. Check the passage in context, including unchanged passages that a later reader challenges. If the evidence does not settle the point, reopen the same issue. Keep the file check separate from your scientific judgment and from any decision by the original reviewers.

Review the file the author asked to deliver, following [the submission route](../ai4sci-paper/references/submission.md). For Markdown, read the exact `.md` alongside the reply and evidence. Markdown alone needs neither `submission.json` nor a Word/PDF check. For Word or PDF, open the exact rendered pages, compare the revised passage with the evidence and reply, and check repeated claims, figures, captions and conclusions. Identify the version, reviewer, method, page findings and open discrepancies. If page inspection is unavailable, report it as pending.

- **Outside Word/PDF, existing evidence:** Preserve the original and inspect the actual revised file. Identify missing historical materials and which claims they limit. Do not reconstruct a native plan or run. If current canonical copies, a delivery manifest and bound review are available, `python3 "$KIT/checks/submission.py" "$STUDY"` is an optional package diagnostic. It checks current bytes and extracted statements, not historical evidence or reviewer independence.
- **Outside Word/PDF with a new comparison:** Audit only the separate native supplement with `python3 "$KIT/ai4sci.py" audit "$SUPPLEMENT"`. Review the revised outside file, its reply and the supplement's findings together. Report the supplement audit and the outside page review separately.
- **Native Word/PDF submission:** Bind the rendered review to the actual package, canonical manuscript and ledger. Run `python3 "$KIT/ai4sci.py" audit --submission "$STUDY"` before handoff. A package-only check cannot replace that audit.
